# 0002. The order of the phases

Date: 2026-10-31. State: accepted (proposed to the user with the plan).

## Context

The user named, in their words: 1 (the web), 2 (being in it, with perception modes), skip 3, 4 (civil), 5 (topology and mating), and faster search with a names index, and the phone app; and asked to structure first.

## Options

1. The user's numbering as it stands: web, being in it, civil, topology
2. Structure, then interfaces (the advantage), search beside them, the web when hosting is chosen, being in it, civil, Moosky

## Choice

The second. The web waits on a choice only the user can make (hosting, `QUESTIONS.md` U1), so work that needs no choice goes first; civil needs both the interfaces (bolted connections) and the names index (its vocabulary), so it comes after them; being in it is tested properly only on real devices, after the web.

## The assumption it rests on

That the user agrees the interfaces are the core advantage (they said so, 2026-10-31: "you said we have a competitive advantage with my logic using the bolt as an example I appreciate that").

## When to test it again

When the user answers U1: the web moves up to the next free slot.
